1.2 UV environments

Story problem

Sharing your Auckland transport analysis

You’ve built a Python script that analyses bus routes in Auckland. Your supervisor wants to run it, but:

  • They use Windows, you use macOS
  • They have different versions of packages installed globally
  • When they run your code, it crashes with import errors

Solution: Virtual environments ensure your project works anywhere, anytime.

What you will learn

  • Understand why virtual environments matter
  • Create and manage environments with uv
  • Add packages and lock versions for reproducibility
  • Run scripts consistently with uv run
  • Share projects that “just work”

Understanding virtual environments

The problem: Global installations

Imagine this scenario:

Your computer (global Python):
├── pandas 2.0.0
├── geopandas 0.14.0
└── numpy 1.24.0

Project A needs:        Project B needs:
├── pandas 2.0.0       ├── pandas 1.5.0  ❌ Conflict!
├── geopandas 0.14.0   ├── geopandas 0.12.0
└── numpy 1.24.0       └── numpy 1.23.0

Problem: You can’t have two versions of pandas installed globally!

The solution: Virtual environments

Each project gets its own isolated environment:

Your computer:
├── Project A/
│   └── .venv/           ← Isolated environment
│       ├── pandas 2.0.0
│       ├── geopandas 0.14.0
│       └── numpy 1.24.0
└── Project B/
    └── .venv/           ← Separate isolated environment
        ├── pandas 1.5.0
        ├── geopandas 0.12.0
        └── numpy 1.23.0

Benefits: - No conflicts between projects - Each project has exactly what it needs - Easy to share and reproduce

Key uv commands

Command Purpose
uv init Create a new project
uv venv Create virtual environment
uv add <package> Install a package
uv remove <package> Uninstall a package
uv sync Install all locked dependencies
uv run <command> Run command in environment
uv pip list List installed packages
uv lock Update lock file

Understanding uv.lock

Open uv.lock - it’s long! It contains:

[[package]]
name = "pandas"
version = "2.2.3"
source = { registry = "https://pypi.org/simple" }
dependencies = [
    { name = "numpy" },
    { name = "python-dateutil" },
    { name = "pytz" },
]
...

Purpose: This file locks exact versions of every package and dependency.

Result: Anyone who runs uv sync gets identical package versions.

Important

Always commit uv.lock to Git! This ensures reproducibility.

Running code in your environment

Option 1: Using uv run (recommended)

Create a script called test.py:

import pandas as pd
import geopandas as gpd

print(f"pandas: {pd.__version__}")
print(f"geopandas: {gpd.__version__}")

# Create sample data
df = pd.DataFrame({
    'park': ['Albert Park', 'Victoria Park', 'Myers Park'],
    'area_ha': [6.0, 7.5, 4.0]
})

print("\nAuckland parks:")
print(df)

Run it with uv run:

uv run python test.py
Screenshot placeholder

[SCREENSHOT NEEDED: Terminal showing uv run output with package versions and data table]

What uv run does: 1. Automatically activates the virtual environment 2. Runs your command 3. Deactivates when done

Advantage: You never need to manually activate/deactivate!

Option 2: Manually activating the environment

If you prefer traditional activation:

  • macOS
  • Windows
source .venv/bin/activate

Your prompt changes to:

(.venv) user@computer auckland-greenspaces %
.venv\Scripts\Activate.ps1

Your prompt changes to:

(.venv) PS C:\Users\user\Documents\auckland-greenspaces>

Now you can run Python directly:

To deactivate:

Tip

Recommendation: Use uv run instead of manual activation. It’s simpler and less error-prone.

Remove a package

uv remove folium

This: - Uninstalls folium - Removes it from pyproject.toml - Updates uv.lock

Upgrade packages

To upgrade all packages to latest compatible versions:

uv lock --upgrade
uv sync
Warning

Be cautious with upgrades! Test your code after upgrading packages.

Recreating environments

Scenario: Colleague wants to run your project

Your colleague clones your project:

git clone https://github.com/your-username/auckland-greenspaces.git
cd auckland-greenspaces

They see:

auckland-greenspaces/
├── pyproject.toml     ✅
├── uv.lock           ✅
├── src/
│   └── analysis.py
└── README.md

Note: No .venv folder! It’s not tracked in Git.

They run two commands:

uv venv          # Create virtual environment
uv sync          # Install exact versions from uv.lock

Now they have exactly the same environment as you!

Best practices

1. Project structure

Organise your project like this:

auckland-greenspaces/
├── .venv/                 # Virtual environment (not in Git)
├── .gitignore            # Ignore .venv and data
├── data/
│   ├── raw/             # Original data
│   └── processed/       # Cleaned data
├── src/                 # Python source code
│   ├── __init__.py
│   ├── data_loader.py
│   └── analysis.py
├── notebooks/           # Jupyter notebooks
│   └── exploration.ipynb
├── tests/               # Unit tests
│   └── test_analysis.py
├── pyproject.toml       # Dependencies (in Git)
├── uv.lock             # Locked versions (in Git)
└── README.md           # Documentation

2. What to commit to Git

Commit: - ✅ pyproject.toml - ✅ uv.lock - ✅ Source code - ✅ Documentation - ✅ Small sample data (<10MB)

Don’t commit: - ❌ .venv/ folder - ❌ Large data files - ❌ Outputs you can regenerate - ❌ Sensitive credentials

3. Create a .gitignore

Create .gitignore in your project root:

# Virtual environments
.venv/
venv/
env/

# Python
__pycache__/
*.py[cod]
*.egg-info/
.pytest_cache/

# Data files
data/raw/
*.csv
*.shp
*.tif
*.gpkg

# Outputs
outputs/
*.png
*.pdf
reports/*.html

# Jupyter
.ipynb_checkpoints/

# IDEs
.vscode/
.idea/
*.swp

# OS files
.DS_Store
Thumbs.db

4. Document your environment

Add to README.md:

# Auckland Green Spaces Analysis

## Setup

1. Clone repository:
   ```bash
   git clone https://github.com/your-username/auckland-greenspaces.git
   cd auckland-greenspaces

  1. Create environment:

    uv venv
uv sync

  2. Run analysis:

    uv run python src/analysis.py

Requirements

  • Python 3.12+
  • uv package manager

Mini exercise

Exercise 1: Create a GIS project

  1. Create a new project called nz-cities-analysis
  2. Initialise with uv init
  3. Create virtual environment
  4. Install: geopandas, matplotlib, contextily
  5. Create a script that:
    • Creates a GeoDataFrame with Auckland, Wellington, Christchurch
    • Prints the coordinates
    • Plots them on a map

Starter code:

import geopandas as gpd
import matplotlib.pyplot as plt
from shapely.geometry import Point

# Create GeoDataFrame
cities = gpd.GeoDataFrame({
    'city': ['Auckland', 'Wellington', 'Christchurch'],
    'geometry': [
        Point(174.7633, -36.8485),
        Point(174.7762, -41.2865),
        Point(172.6362, -43.5321)
    ]
}, crs='EPSG:4326')

print(cities)

# Plot
cities.plot(marker='o', color='red', markersize=100)
plt.title('Major New Zealand Cities')
plt.savefig('nz_cities.png', dpi=300, bbox_inches='tight')
print("✅ Map saved to nz_cities.png")

Run with:

uv run python analyse_cities.py

Troubleshooting

Package installation fails

Problem: uv add package-name fails with dependency conflict

Solution:

uv add package-name --prerelease=allow

Or specify a version:

uv add "pandas<2.0.0"

Wrong Python version

Problem: Virtual environment uses wrong Python version

Solution:

uv venv --python 3.12

Environment activation fails (Windows)

Problem: PowerShell blocks script execution

Solution:

Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser

Can’t find installed packages

Problem: Import error even after uv add

Solution: Make sure you’re using uv run:

uv run python your_script.py

Not just:

python your_script.py
